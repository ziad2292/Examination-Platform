## Reproduction and release

Use local Supabase only and disposable fixture data. Start the preview with `NEXT_DIST_DIR=.next-audit`, `npm run build`, then `next start -p 3005`. The normal app still uses its original output directory. The browser scripts use known local seed accounts and reject no production URL because their origin is hardcoded localhost. Database audit script hardcodes the local Docker container and generates a fresh database name. Do not repoint them to production.

Run `npm run lint`, `npm run typecheck`, `npm test`, `scripts/audit/database-baseline.ps1`, and the existing Playwright suite with local-only fixture flags. Registration tests require the local service-role key in the process environment and local mail service. Never write credentials to reports. Run `node scripts/audit/browser-baseline.mjs final` and `node scripts/audit/accessibility.mjs` on the production preview. For native non-Windows CI, explicitly configure a browser executable or update the existing Windows-specific Playwright default.

Release from a reviewed commit after staging verification. Install the lockfile with npm ci, configure server-only credentials and public feature flags for the correct environment, then build. Dependency updates were completed using npm 11 after npm 10's resolver failed; global npm was not changed. Verify clean npm ci on CI before promotion. No automatic deployment or remote migration was performed.

For the prior feature migrations, separately review unapplied versions, back up the database, apply them through the existing deployment procedure, and smoke-test the matching app release. Do not roll back by dropping new data. This audit itself requires no new schema change.
